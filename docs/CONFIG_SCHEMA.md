# Configuration Schema

All configuration objects are validated server-side with Pydantic.

## `SensorConfig`

| Field          | Type                  | Default | Notes                                   |
|----------------|-----------------------|---------|-----------------------------------------|
| `id`           | string                | auto    | Read-only, generated by the server.     |
| `name`         | string                | —       | Required. Unique (case-insensitive). 1-80 chars. |
| `interval_sec` | float                 | `1.0`   | `0.05`–`3600`.                          |
| `jitter_sec`   | float                 | `0.0`   | Random extra delay in `[0, jitter_sec)`. |
| `fields`       | array of FieldConfig  | `[]`    | At least one is recommended.            |
| `outputs`      | array of OutputConfig | `[screen]` | Multiple may be combined.            |
| `anomaly`      | AnomalyConfig         | disabled | See below.                             |
| `running`      | bool                  | `false` | If true, the sensor starts on creation. |

## `AnomalyConfig`

| Field        | Type   | Default | Notes                              |
|--------------|--------|---------|------------------------------------|
| `enabled`    | bool   | `false` |                                    |
| `probability`| float  | `0.0`   | `0`–`1`. Probability per sample.   |
| `min_factor` | float  | `1.5`   | Lower bound of the spike factor.   |
| `max_factor` | float  | `3.0`   | Upper bound of the spike factor.   |

When triggered, a randomly-chosen numeric field is multiplied by a uniform
`[min_factor, max_factor]` factor (with a 50% chance of being inverted, to
produce downward spikes). The payload is annotated with `_anomaly: { field, factor }`.

## `FieldConfig` variants

```jsonc
{ "type": "timestamp",      "name": "ts",  "fmt": "iso" }              // iso | epoch_ms | epoch_s
{ "type": "fixed_number",   "name": "x",   "value": 42 }
{ "type": "random_number",  "name": "t",   "min": 0, "max": 100, "decimals": 2 }
{ "type": "fixed_string",   "name": "s",   "value": "ok" }
{ "type": "random_string",  "name": "tok", "length": 8, "charset": "alnum" }
{ "type": "pattern_string", "name": "id",  "pattern": "DEV-{d:4}-{seq}" }
{ "type": "file",           "name": "loc", "path": "/app/sample_data/locations.txt", "mode": "loop" }
```

`charset`: `alpha` | `alnum` | `digits` | `hex`.

`mode`: `sequential` (stops at EOF), `loop` (wraps), `random`.

### Realistic generators (v1.2.0)

These model real-world signals far better than an independent uniform draw:

```jsonc
// Normally-distributed sensor noise around a mean (optional clamp with min/max).
{ "type": "gaussian_number", "name": "r", "mean": 20, "stddev": 2, "decimals": 2, "min": null, "max": null }

// Random walk — the reading drifts by at most ±step each sample and stays in [min, max].
// Ideal for slow-moving quantities: temperature, tank level, battery %.
{ "type": "random_walk", "name": "level", "start": 50, "step": 1, "min": 0, "max": 100, "decimals": 2 }

// Deterministic periodic signal: value = offset + amplitude*sin(2*pi*t/period_sec + phase) + noise
// where t = seconds since the sensor started. Great for daily temperature/energy cycles.
{ "type": "sine_wave", "name": "cycle", "amplitude": 10, "offset": 20, "period_sec": 60, "phase": 0, "noise": 0, "decimals": 2 }

// Boolean flag, True with probability p_true.
{ "type": "boolean", "name": "flag", "p_true": 0.5 }

// Categorical value, optionally weighted (weights length must equal values length).
{ "type": "enum", "name": "state", "values": ["ok", "warn", "fault"], "weights": [8, 1, 1] }

// Random UUID v4 — message/event ids.
{ "type": "uuid", "name": "uuid" }

// GPS point jittered within radius_m of a center, emitted as {"lat": .., "lon": ..}.
{ "type": "geo_point", "name": "location", "lat": 40.4168, "lon": -3.7038, "radius_m": 500, "decimals": 6 }
```

## `OutputConfig` variants

```jsonc
{ "type": "screen",   "enabled": true }

{ "type": "mqtt",
  "enabled": true,
  "host": "broker.hivemq.com",
  "port": 1883,
  "topic": "iot/sim/{sensor}",
  "qos": 0,
  "retain": false,
  "tls": false,
  "username": null,
  "password": null,
  "client_id": null }

{ "type": "kafka",
  "enabled": true,
  "bootstrap_servers": "localhost:9092",
  "topic": "iot-sim",
  "key_field": null }

{ "type": "tcp_json",
  "enabled": true,
  "host": "127.0.0.1",
  "port": 5050 }

{ "type": "file_output",
  "enabled": true,
  "path": "/app/output/sensor.jsonl",
  "mode": "append",          // append | overwrite
  "format": "jsonl" }        // jsonl | json_pretty

{ "type": "http",            // HTTP webhook — the most common cloud-ingestion pattern
  "enabled": true,
  "url": "https://collector.example.com/ingest",
  "method": "POST",          // POST | PUT
  "headers": { "X-Api-Key": "..." },
  "bearer_token": null,      // sets Authorization: Bearer <token>
  "basic_user": null, "basic_pass": null,
  "timeout_sec": 5.0,
  "verify_tls": true }

{ "type": "amqp",            // AMQP 0-9-1 (RabbitMQ)
  "enabled": true,
  "url": "amqp://guest:guest@localhost:5672/",
  "exchange": "",            // "" = default exchange
  "routing_key": "iot.sim.{sensor}" }

{ "type": "coap",            // CoAP (RFC 7252) — constrained/low-power IoT over UDP
  "enabled": true,
  "uri": "coap://localhost:5683/ingest",
  "method": "POST" }         // POST | PUT
```

The `topic` of an MQTT output and the `routing_key` of an AMQP output support
the `{sensor}` placeholder, replaced by the sensor's name at publish time.

The `key_field` of a Kafka output, if set and present in the payload, is used
as the Kafka message key (helps with partitioning per device).

## `EncryptionConfig` (optional, per output)

Any transport output (everything except `screen`) may carry an optional
`encryption` block. When enabled, the JSON payload is replaced with an
AES-256-GCM envelope before it leaves the process:

```jsonc
{ "type": "mqtt", "...": "...",
  "encryption": {
    "enabled": true,
    "algorithm": "AES-256-GCM",
    "key_env": "METER_KEY",   // read a base64-encoded 32-byte key from this env var (recommended)
    "key_b64": null           // …or supply the base64 key inline (avoid committing to exports)
  } }
```

The envelope shape is:

```json
{ "enc": "AES-256-GCM", "iv": "<b64>", "ct": "<b64>", "tag": "<b64>", "aad": "<sensor-name>" }
```

`iv` is a fresh 96-bit nonce per message, `ct` the ciphertext, `tag` the 128-bit
GCM authentication tag, and `aad` the sensor name (authenticated but not
encrypted). Generate a key with:

```bash
python -c "import os,base64; print(base64.b64encode(os.urandom(32)).decode())"
```
